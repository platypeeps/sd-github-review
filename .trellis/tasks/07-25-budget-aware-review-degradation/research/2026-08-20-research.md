## Current State

### The live routing path has no chain, candidate, or budget concept

The Action entrypoint resolves a route through a pure risk-based decision and then
picks a model from two flat Action inputs:

- `src/index.js:254` calls `routeReview(...)`, the only routing call on the
  standalone path.
- `src/router.js:22-69` `routeReview` returns one of `none|cheap|deep|copilot`
  from draft state, sensitive files, changed-line threshold, and prior
  confidence. There is no candidate, chain, budget, or reservation input.
- `src/index.js:275-280` selects the model with
  `input("cheap-model")` / `input("deep-model")` — a single fixed model per lane.
- `src/normalize.js:48-51` `parseReviewCommand` matches
  `/^\s*\/review\s+(auto|cheap|deep|copilot|none)\s*$/iu`. The trailing `\s*$`
  anchor means `--candidate`, `--slot`, and `/review options` are not merely
  unimplemented on this path — they are syntactically rejected.

`selectProtocolRoute` (`src/router.js:104-210`) is the v1 durable-operation
policy. It adds floors, local evidence, and successor handling, but still emits a
single route and no candidate.

## Gaps vs PRD

### G1 (blocking, parent-owned) — the ordered chain has no compiled representation

This is the parent's headline deliverable and it is the one thing the built
pieces cannot express end to end. There are **three mutually incompatible chain
representations**, and no producer connects any of them:

1. `prepareManagedPlan` takes `chain` as a **caller-supplied array**
   (`src/review-plan-authorization.js:713`), validated at 730-736 as
   "at least one considered candidate in the named lane order". It has no
   producer outside tests.
2. `routed-review-compiler.js` emits **exactly one candidate per lane** —
   `lanes[lane] = { slot, budgetExhaustion: { merge }, candidate: {…} }`
   (`src/routed-review-compiler.js:407-418`, the file's only `lanes[lane] = …`
   assignment). Worse, it *actively forbids*
   chains: `"chain"` and `"chains"` are in `FORBIDDEN_COMPOSITION_LEVERS`
   (`src/routed-review-compiler.js:68-69`), rejected by normalized key at any
   depth with "a compiled v2 configuration declares no … chain reference"
   (thrown at `src/routed-review-compiler.js:129`).
3. `protocol-v2.js` carries a *separate* chain model: `reviewerCatalog.chains`
   decoded at `src/protocol-v2.js:1536-1561`, slot selector kind `chain` in
   `decodeSlotSelector` at `1427-1440`, `MAX_CHAIN_MEMBERS = 8` at `72`,
   unknown-chain rejection at `1582-1584`.

So the compiled contract that the runtime is supposed to be the sole consumer of
(`design.md:240-242`, `prd.md:98-103`) structurally *cannot* carry the ordered
chain, while the planner that consumes chains has no way to obtain one. Every
PRD acceptance criterion about ordering is unreachable through the compiler:
`prd.md:302-304` (Copilot → Kimi → third candidate), `prd.md:305-306`
(`deep-independent` never selects Copilot implicitly), `prd.md:307-309`
(cheap chain), `prd.md:200-204` (first eligible in the applicable named chain).

### G2 (blocking) — lane and slot vocabulary diverged from PRD and design

- PRD and design treat lanes as the logical `cheap`/`deep` policy lanes
  (`prd.md:11`, `prd.md:211`, compiled example `design.md:255-264`).
- Code defines `REVIEW_LANES = ["review", "assurance", "gate"]`
  (`src/protocol-v2.js:61`, duplicated at `src/review-candidate-catalog.js:58`).
  These are *check* lanes, not cost lanes. `src/review-plan-authorization.js:26,51`
  imports and enforces that set, so `prepareManagedPlan(lane: "gate")` is the
  tested shape (`test/review-plan-authorization.test.js:208`).
- `CANDIDATE_SLOTS = ["managed", "parallel"]` (`src/protocol-v2.js:64`), but
  `prd.md:108-111` requires each v2 lane to materialize one explicit required,
  overridable slot named **`primary-review`**, which is also what
  `design.md:283-303` shows. `primary-review` exists nowhere in `src/`; its only
  appearance anywhere in the tree is as a *rejected* input in
  `test/protocol-v2.test.js:909`, where `assertReviewerSelectionLabel("primary-review")`
  is asserted to throw "must be a broad review lane label".

Consequence: `prd.md:211` ("Preserve `selected_lane=cheap|deep` for every
candidate") cannot be satisfied by the current constant set, and design.md's
compiled-contract example is not the shape that was built.

## Open Questions

1. **Which lane vocabulary wins?** Are `cheap`/`deep` the compiled lane keys with
   `review`/`assurance`/`gate` a separate check axis, or did the code
   deliberately collapse them? `prd.md:211` requires the former; the code asserts
   the latter. This blocks G1 and G2 together and needs an owner decision before
   any child starts.
2. **Where do chains live — compiled manifest or pinned catalog?**
   `routed-review-compiler.js:68-69` forbids them in the compiled config while
   `protocol-v2.js:1536-1561` decodes them from `reviewerCatalog`. If the catalog
   is the intended home, `design.md:265-278` (`candidateChains` in the compiled
   manifest) is wrong and the forbidden-lever list is right.
3. **How do `REVIEW_ROUTE_MODE` and v2 lane policy coexist?** Does the v2 source
   file supersede route mode, or does route mode remain the coarse switch with
   the source file refining within it?
4. **Who owns the control-plane contract now that G5's task is missing?** Recreate
   it, or fold it into `07-25-compile-and-execute-budget-aware-review-plans`?
5. **Does distribution still gate this?** The park required v1 to be distributed
   to fleet consumers. Not verifiable from this repo — it needs a probe of
   consumer repos for `config/routed-review-setup-v1.json`. **Not verified here.**

## Recommendations

1. **Resolve Open Questions 1 and 2 before starting any child.** They are
   contract-shape decisions that determine whether the compiler, the catalog
   decoder, or both must change. Starting the installer or adapter child first
   would build against a shape that may move.
2. **Make G1 the first implementation step**, ahead of `implement.md`'s current
   ordering. The minimum coherent slice is: compiled manifest (or pinned catalog)
   gains an ordered chain per lane → a producer function derives
   `prepareManagedPlan`'s `chain` argument from it → one end-to-end test walks
   Copilot → Kimi → third candidate. Until that exists, every downstream budget,
   receipt, and check behavior is untestable in situ.
3. **Do not treat the 71.5% unreachable code as sunk cost or as done.** It is
   green at module level and genuinely close to the PRD in the reservation,
   reconciliation, deferral, and retention areas. Reuse it. But its lane/slot
   constants and the compiler's single-candidate output need reconciling with the
   PRD before wiring, or wiring will lock in G2.
4. **Refresh setup discovery (G3) as its own small, early step.** It is the
   handshake the command pack and installer both read; leaving it at
   `contractMajor: 1` will make every downstream integration report v1
   capabilities regardless of what ships.
5. **Recreate or reassign the control-plane contract task (G5)** before the
   adapter child starts, since the adapter's bounded acknowledgment is defined
   against that contract.
6. **Re-verify the park premises before committing to implementation.** The
   reachability premise still holds (verified above). The distribution premise
   was not verified in this run.

## Cross-Child Integration Criteria

Conditions the parent should enforce at each child boundary.

**`07-25-deliver-routed-review-configuration` (installer/source/migration)**
- Writes a source file whose compiled output carries an *ordered* chain per lane;
  a single-candidate compile is a failure, not a valid degenerate case.
- Records `REVIEW_ROUTE_MODE` coherently with the v2 source; a repo at manifest
  schema 4 must not end up with route mode and source file disagreeing.
- Bumps `MANIFEST_SCHEMA_VERSION` past 4 only with the migration path added to
  `SUPPORTED_MANIFEST_SCHEMA_VERSIONS` (`codecs.mjs:159-160`).
- Never provisions `review-candidate:*` / `review-slot:*` labels (`prd.md:148-151`).

**`07-25-compile-and-execute-budget-aware-review-plans` (schemas/compiler/runtime)**
- Owns the G1 fix. Exit criterion: `compileRoutedReviewConfiguration` output feeds
  `prepareManagedPlan`'s `chain` with no test-only glue.
- Reconciles the three chain representations down to one, and the lane/slot
  vocabulary to one (G2).
- Makes the engine reachable from `src/index.js`. A re-run of the import-graph
  walk must show the budget modules reachable; that is the parent's single
  clearest done-signal.
- Refreshes `config/` + `contract/` setup discovery (G3) — both copies.

**`07-25-integrate-authorized-review-adapters` (Copilot + external execution)**
- Consumes an already-authorized immutable candidate; performs no selection.
- Verifies prompt-profile digest before dispatch and rejects a substituted
  profile (`design.md:433-440`) — the compiler already enforces binding equality
  at `src/routed-review-compiler.js:444-446`, so the adapter must not re-derive it.
- Keeps `CONFIG__FALLBACK_MODELS=[]` (`prd.md:115-116`).
- Must not start before the lane vocabulary is settled: it dispatches per lane.

**Parent-level gates (all children)**
- No hard-coded provider, model, or chain name in routing, receipts, or budget
  logic (`prd.md:94-97`).
- No management credential or ledger state in this repository (`prd.md:273-275`).
- `npm test` stays green; current baseline is 647 passing.
- Every new outcome is explicit — no silent fallback (`check.jsonl` requires
  exhausted/unknown/unavailable/ambiguous/recovery to be distinct).
