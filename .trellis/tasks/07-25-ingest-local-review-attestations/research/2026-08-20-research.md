### The compiled route and its trust policy exist

`STANDALONE_EXECUTIONS = ["direct-handler", "local-attested"]` — `src/protocol-v2.js:44`.

### Nothing ingests an attestation at runtime

This is the central gap.

- The Action's operation set is five entries — `standalone`, `route`,
  `acknowledge`, `finalize`, `query` — declared in `OPERATION_LIST`,
  `src/operation-contract.js:26-132`. There is no ingestion/attest operation.
- No `src/` module outside `src/protocol-v2.js` references
  `decodeLocalReviewReceipt` or `authorizeProjectionWrite` (repo-wide grep over
  `src/` returns only `src/protocol-v2.js`).
- `src/protocol-v2.js` is unreachable from the Action entrypoint. `src/index.js`
  imports `github.js`, `operations.js`, `risk-context.js`, `reviewer-dispatch.js`,
  `router.js` (`src/index.js:1-17`); `src/operations.js` imports `protocol.js`,
  `receipt.js`, `router.js`, `risk-context.js`, `reviewer-dispatch.js`,
  `normalize.js`, `operation-contract.js` (`src/operations.js:1-18`). Neither
  reaches `protocol-v2.js`.
- `scripts/check-coverage.mjs:29-47` records this explicitly: a transitive walk
  from `src/index.js` and `src/operations.js` reaches 11 of 19 modules; the other
  8 (including `src/protocol-v2.js` and `src/routed-review-compiler.js`) are
  listed as unreachable and total ~9,390 of 13,136 lines under `src/`. This is the
  same figure quoted in the task's park rationale, and it is still accurate.

### How the Action consumes external review evidence today (v1)

There *is* a shipped local-evidence path, but it is a different, weaker thing
than what this task specifies:

- `decodeLocalReviewSummary` — `src/protocol.js:388-460`. A bounded
  `localReview` summary nested **inside the caller-supplied `review-request`**:
  providers, `outcome` (`LOCAL_OUTCOMES`), `confidence`, `dispositionCounts`,
  `receiptId`, `scopeDigest`, `configurationDigest`, `latencyMs`, `costTier`.
  It cross-checks repository / PR number / headSha against the request
  (`src/protocol.js:452-461`) — that is, against other caller-supplied fields.
- `selectProtocolRoute` — `src/router.js:104`. Local evidence is **advisory
  routing only**: eligible exact-head evidence may *lower* an `auto` route toward
  `localEvidenceRoute` (`src/router.js:161-178`); it is `ignored-explicit` when the
  route is not `auto` (`src/router.js:143`). It never satisfies assurance and never
  passes a gate.
- Policy inputs are read at `src/operations.js:389-402`
  (`independent-review-floor`, `local-confidence-threshold`,
  `local-evidence-route`), declared for the `route` operation at
  `src/operation-contract.js:79-81`.
- `receipt.localEvidence` is decodable (`src/protocol.js:914-926`:
  `receiptId`, `digest`, `contribution`) but **no `src/` module ever writes it** —
  grep for `localEvidence` in `src/` hits only `protocol.js` and `router.js`.
  It is dead durable-contract surface today.

Trust today: the v1 path applies **no** actor/association/PR-author/age policy to
local evidence at all. Association checking exists only in the `standalone`
comment-command path, from the event payload
(`src/index.js:207` `event.comment?.author_association`, trusted set at
`src/index.js:200-204`, default `OWNER,MEMBER,COLLABORATOR`).

### Exact-head verification today

`src/operations.js:350-352` reads the live PR once and throws if
`liveHead(pullRequest) !== request.headSha`. That is a single pre-dispatch read.
The design's requirement of a re-read *before receipt creation* and *again before
returning an accepted result* is strictly stronger and unimplemented.

### GitHub-derived context available today

Only `GITHUB_REPOSITORY`, `GITHUB_SERVER_URL`, `GITHUB_RUN_ID` are read
(`src/operations.js:79-80`, `src/operations.js:549`, `src/index.js:193`,
`src/github.js:167`). There is **no** read of `GITHUB_ACTOR`,
`GITHUB_WORKFLOW_REF`, or `GITHUB_RUN_ATTEMPT`, and no API resolution of an
actor's `author_association` for a PR. Every field
`decodeLocalPublicationContext` requires (`src/protocol-v2.js:1146-1159`) must be
newly derived.

## Staleness in existing design/implement

Both `design.md` and `implement.md` date from 2026-07-25 and predate the shipped
contracts. They are **directionally correct and not contradicted by the code** —
the validation order, the reconciliation rule, and the child-operation split all
match what `protocol-v2.js` actually enforces. The staleness is in the PRD and
the parent design, not primarily in these two files.

Concrete stale facts found:

1. **`cancelled` is not a review result.** `prd.md` acceptance criterion 1 asks
   for "clean, findings, failed, and cancelled fixtures", and the parent
   `design.md` Attestation Contract says `clean|findings|failed|cancelled`. The
   shipped enum is `LOCAL_REVIEW_RESULTS = ["clean", "findings", "error"]`
   (`src/protocol-v2.js:86`), with outcome classes
   `completed_local | completed_local_findings | awaiting_local_attestation |
   failed_local` (`src/protocol-v2.js:92-97`). `failed` and `cancelled` both
   collapse into `error` / `failed_local`.
2. **Named trust policies were dropped.** The parent `design.md` Source Shape
   shows a `localAttestationPolicies:` map with `routes.cheap.policy:
   workstation-review`. The shipped decoder requires an *inline* `attestation`
   object per route and forbids a `policy` key indirection
   (`src/protocol-v2.js:568-570`, `src/protocol-v2.js:523-541`). Field names also
   changed: `allowPullRequestAuthor` -> `allowPrAuthor`, `maximumAge: 24h` ->
   `maxAgeSeconds` integer.
3. **`npm run check` does not cover v2 modules.** `implement.md` step 5 lists
   `npm run check` as validation. That script is a hand-enumerated
   `node --check` list (`package.json:12`) that omits `src/protocol-v2.js` and
   `src/routed-review-compiler.js` entirely. A new ingestion module gets no
   syntax check unless it is added to that list, and coverage requires touching
   `scripts/check-coverage.mjs:29-47`.
4. **Distribution has moved.** The task park rationale referenced probing fleet
   consumers for `config/routed-review-setup-v1.json`; that file still declares
   `contractMajor: 1` and only `route|finalize|query`
   (`config/routed-review-setup-v1.json`), while the installer has advanced
   independently to manifest v4 with installer-managed `REVIEW_ROUTE_MODE`
   (`scripts/consumer-installer/codecs.mjs:159`, `:138`). The descriptor and the
   installer are now two versions apart on how a consumer is configured.

## Open Questions

1. **How does the ingestion operation reach `protocol-v2.js`?** Options: extend
   the `ALLOWED` matrix for `operations.js`; or add a sibling module
   (e.g. `src/local-attestation-ingest.js`) allowed to import `protocol-v2.js` and
   `github.js`, dispatched from `index.js` rather than `operations.js`. This is an
   architecture decision the plan must make explicitly, not discover.
2. **Where does `policyDigest` come from?** The compiled manifest exposes
   `sourceDigest` and `outputDigest` (`src/routed-review-compiler.js:361-364`),
   and the receipt binds both `configurationDigest` and `policyDigest`
   separately. Which compiled digest maps to which receipt field is unspecified.
3. **How is `association` resolved?** No API call in `src/github.js` returns an
   arbitrary actor's `author_association` for a PR. Adding one expands the
   client surface and the operation's declared permissions
   (`src/operation-contract.js:24-25` requires permissions be grounded in the
   client methods invoked).
4. **Where is the attempt receipt stored?** A second Check Run alongside
   `sd-github-review/receipt`? Under one of the v2 Check names? The v2 names are
   projection surfaces, and the design says projection is a *separate* child
   operation — so the receipt likely needs its own durable location.
5. **Is `maxAgeSeconds` evaluated against `producedAt` or a GitHub-derived
   received time?** The contract carries `producedAt` (caller-asserted) with no
   received-time field. A caller-asserted timestamp alone cannot bound evidence
   age safely; the plan should say which clock governs.
6. **Does this task remain wanted?** The park was lifted by owner directive, but
   the park's own falsification test still holds: `protocol-v2.js` remains
   unreachable from `src/index.js`, and `ROUTE_MODES` has no local-attested value,
   so no installed consumer can select this lane.

## Recommendations

1. **Do not re-plan the contracts.** They shipped, they are fixtured, and they
   are tested. Scope this task to runtime: derivation, policy evaluation, head
   re-read, receipt persistence, and negative proof.
2. **Decide the module boundary before writing code** (Open Question 1). A new
   `src/local-attestation-ingest.js` registered in
   `test/dependency-boundaries.test.js` keeps `operations.js` from gaining a v2
   dependency and keeps the v1 durable path untouched.
3. **Correct the `cancelled` fixture expectation** in `prd.md` acceptance
   criterion 1 to `clean`, `findings`, and `error` (mapping to `completed_local`,
   `completed_local_findings`, `failed_local`) before implementation starts.
4. **Add the age check explicitly.** `maxAgeSeconds` is decoded but never
   applied anywhere in `src/`. It is this task's requirement to apply it, and the
   governing clock must be chosen.
5. **Extend the validation surface, not just the code.** Any new module must be
   added to `package.json` `check`, `scripts/check-coverage.mjs`, and
   `test/dependency-boundaries.test.js` or CI will silently under-verify it.
6. **Treat distribution as a separate, still-open concern.** Ingestion can be
   built and tested in isolation, but until `ROUTE_MODES`
   (`scripts/consumer-installer/codecs.mjs:122`) and
   `config/routed-review-setup-v1.json` learn about the local-attested lane, no
   consumer can invoke it. That belongs to the installer/descriptor tasks, and
   this task should record the dependency rather than absorb it.
