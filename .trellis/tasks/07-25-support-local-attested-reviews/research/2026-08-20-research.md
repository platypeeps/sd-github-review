## Gaps vs PRD

Ordered by how much they change the delivery shape.

1. **Envelope is thinner than the PRD requires.** `prd.md:32-38` asks the
   attestation to bind review tool/profile identity, terminal outcome, finding
   and disposition counts, start *and* finish times, and a stable reason.
   `decodeLocalAttestationRequest` (`src/protocol-v2.js:1182-1206`) binds only
   `repository, pullRequestNumber, headSha, lane, attempt, configurationDigest,
   localReceiptDigest, contentDigest, evidenceDigest, reviewResult, producedAt`
   plus optional self-reported usage. Tool/profile identity, counts, a
   start/finish pair, and a reason code are absent. The reason codes exist as an
   enum (`src/protocol-v2.js:142-148`) but the request cannot carry one.
   Either the PRD narrows or the envelope grows; today they disagree.

2. **Terminal-outcome vocabulary diverges.** `prd.md:44-47` accepts
   `clean | findings | failed | cancelled`. The shipped enum is
   `clean | findings | error` (`src/protocol-v2.js:86`), with the comment at
   `src/protocol-v2.js:83-85` (comment above it) explaining that `awaiting` is derived by the
   ingestion boundary rather than publisher-reported. The ingest child's
   `design.md` already states the reconciliation ("a cancelled local run reports
   `error`"); the parent PRD does not.

3. **`deferred` assurance is reserved for budget exhaustion, so the awaiting
   state has nowhere to land.** `design.md`'s outcome table maps
   `awaiting_local_attestation` and a stale head to a `deferred` assurance
   state, but `decodeReviewOutcomes` rejects any `deferred` assurance whose
   reason is not `budget_exhausted_deferred`
   (`src/protocol-v2.js:829-832`) — and `prd.md:60-62` explicitly says
   local-attested execution has no budget-deferred pass. Awaiting evidence must
   therefore either map to `fail`, or a local deferral reason must be admitted
   into that guard. This is a contract-level decision that both children
   inherit; it is unresolved today.

4. **No enforcement of trust policy, age, or exact head.** Every authorization
   input is decoded and nothing evaluates it. `maxAgeSeconds`
   (`src/protocol-v2.js:536`), `allowedAssociations` / `allowPrAuthor`
   (`:529-535`), and live-head re-read are all unimplemented. The
   `authorized && reviewResult !== "clean"` invariant at
   `src/protocol-v2.js:1230-1233` is a decode-time assertion, not a policy
   engine.

5. **No projection path.** `decodeCheckProjection` and
   `authorizeProjectionWrite` exist (`src/protocol-v2.js:1324`, `:1351`) but no
   `src/` module writes an `sd-review / assurance` or `sd-review / gate` Check.
   The only Check writer in the reachable runtime is the v1 receipt Check
   (`src/receipt.js:133`).

6. **Acceptance criterion on fixtures is partly met.** `prd.md:70-72` wants
   standalone fixtures for all-local, mixed, and direct-only route
   configurations. `fixtures/protocol/v2/source-contracts.{valid,invalid}.json`
   and `routed-review-source.{valid,invalid}.json` exist; a route-shape audit
   confirming all three combinations is a cheap pre-implementation check worth
   running rather than assuming.

7. **Installer/rollout criterion unmet.** `prd.md` acceptance and
   `design.md:139-145` describe operator-chosen scaffolding, readiness, and
   rollback. Nothing in `scripts/consumer-installer/` models local-attested
   execution at manifest schema 4.

8. **Distribution premise still holds.** The park note on `task.json:28`
   conditioned resumption on v1 actually reaching fleet consumers. Unparking was
   an owner directive (`prd.md` title de-parked in the working tree; `task.json`
   `blockedOn` cleared), not evidence that the premise changed. Reachability is
   re-measured above and is unchanged. Whether consumers now deploy
   `config/routed-review-setup-v1.json` was **not** re-probed in this pass and

## Open Questions

1. Does the envelope grow to carry tool/profile identity, counts, a
   start/finish pair, and a reason code — or does the PRD narrow to the shipped
   digest-only binding? This is the single largest fork; it decides whether the
   contracts child must be reopened before the two active children can start.
2. Is `error` an acceptable collapse of `failed` and `cancelled`, given
   `prd.md:44` distinguishes them and `prd.md:76` names both in an acceptance
   criterion?
3. Where does the v2 receipt live? `src/receipt.js` is v1-only and reachable;
   a v2 store must either be a sibling module or a versioned extension, and the
   choice determines whether `src/index.js` gains a v2 import at all.
4. Does this task ship reachable from `src/index.js`, or does it land as more
   unreachable protocol surface? If the latter, the park premise it was
   unparked against has not actually been retired.
5. How do the two meanings of "local evidence" coexist? v1
   (`src/router.js:157-176`) treats a local summary as a routing *discount* on
   `auto`; v2 treats an attestation as a route *execution kind*. `prd.md:22-23`
   forbids inferring local-attested execution from a local receipt — so the two
   must be provably separated, not merely differently named.
6. Should local-attested execution get a `--route-mode` value, or is it
   orthogonal to route mode (a per-lane execution kind, per `design.md:37-44`)?
   Manifest schema 4 forces an answer before installer work starts.
7. Command-pack publisher (`prd.md:88-90`,
   `platypeeps/sd-ai-command-pack:07-25-publish-local-review-attestations`) —
   state not verified in this pass; it lives in another repository.

## Cross-Child Integration Criteria

The seam between `07-25-ingest-local-review-attestations` and
`07-25-project-local-review-assurance` is the immutable receipt plus the
authorized attempt token. Concretely:

1. **Handoff object.** Ingest produces a value that decodes cleanly through
   `decodeLocalReviewReceipt` (`src/protocol-v2.js:1258`). Projection consumes
   only that; it never sees the raw request or the publisher's transport frame.
2. **Attempt token.** `decodeLocalReviewAuthorization`
   (`src/protocol-v2.js:1211-1257`) derives `attemptToken` over the full
   binding plus `attestationDigest`, `trustLevel`, `policyDigest`, and
   `publicationContext`. That token is the CAS key
   `authorizeProjectionWrite(previous, next, { authorizedAttemptToken })`
   expects (`src/protocol-v2.js:1351`). Ingest must persist it; projection must
   not recompute it from partial inputs.
3. **Gate truth is computed once.** `decodeLocalReviewReceipt` sets
   `gateSatisfied = outcomeClass === "completed_local"`
   (`src/protocol-v2.js:1281`). Projection reads that field; it must not
   re-derive pass/block from `reviewResult`.
4. **Outcome-axis invariants are enforced by the shared decoder.**
   `decodeReviewOutcomes` (`src/protocol-v2.js:806`) rejects a passing
   assurance under any blocking local state (`:840-845`), rejects a passing
   assurance whose review reason is `review_none` (`:850-856`), and forces the
   gate to block on any non-budget failure (`:858-865`). Both children should
   route their outcomes through that decoder rather than asserting
   independently. Note the `deferred` restriction at `:829-832` — see gap 3;
   until it is resolved the two children could legitimately disagree about what
   assurance state an awaiting head produces.
5. **Awaiting state has no evidence digest.**
   `decodeLocalAttestationStatus` (`src/protocol-v2.js:1292-1322`) forbids
   `evidenceDigest` while `awaiting_local_attestation` and requires it for
   every settled state. Ingest owns the transition; projection must tolerate
   both shapes.
6. **Head supersession ownership.** Ingest re-reads the live head before
   receipt creation; projection re-reads before the Check write
   (`design.md:120-125`). Both re-reads are required — a single one leaves a
   window. The children's plans should not each assume the other covers it.
7. **Zero reviewer mutation is a joint property.** `prd.md:73-75` and
   `design.md:67-72` require no review, comment, adapter, or provider call on
   either side. The spy-based negative tests in the ingest child
   (`implement.md:11`) should be mirrored on the projection side rather than
   assumed transitive.
