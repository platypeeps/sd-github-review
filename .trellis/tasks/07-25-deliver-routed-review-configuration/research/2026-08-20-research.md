## Current State

### The installer lifecycle that already exists (v1)

The consumer installer is mature and owns most of the *mechanical* lifecycle
this task's PRD asks for. It is not the v2 configuration lifecycle.

- Entrypoint `scripts/install-consumer.mjs`; orchestrator
  `scripts/consumer-installer.mjs` dispatching `install`, `update`, `adopt`,
  `check`, `uninstall` (`scripts/consumer-installer.mjs:634-642`).
- Decomposed into four leaf modules under `scripts/consumer-installer/`:
  `codecs.mjs`, `transport.mjs`, `persistence.mjs`, `plan.mjs`. The one-way
  layering (orchestrator -> submodules -> codecs) is frozen by an allowed-import
  matrix test (`test/installer-dependency-boundaries.test.js:6-14`).
- Ownership manifest at `.github/sd-github-review.json`
  (`scripts/consumer-installer/codecs.mjs:8`).
- Lifecycle states `pending` / `active` / `uninstalling`
  (`scripts/consumer-installer/codecs.mjs:142`); mutating commands write
  `pending`, mutate GitHub, then mark `active`, so a partial failure is
  resumable (`.trellis/spec/backend/consumer-installer.md:83-84`).
- Managed file resources derive from one table — `workflow`, `descriptor`,
  `durableWorkflow` (`scripts/consumer-installer/codecs.mjs:38-57`).
- `--dry-run` is supported on every mutating command
  (`.trellis/spec/backend/consumer-installer.md:181`).
- Drift reporting lives in `checkInstallation`
  (`scripts/consumer-installer.mjs:403`); ownership-scoped removal in
  `uninstall` (`scripts/consumer-installer.mjs:530`).
- Interrupted-promotion tolerance is explicit: a `pending` manifest suppresses
  the A-013 modification guard so a retry converges rather than refusing
  (`scripts/consumer-installer/plan.mjs:53-58`, `:101-108`).

**Read this as: PRD requirement "make install, update, check, and uninstall
idempotent and preserve unrelated consumer content" is already satisfied for
v1 resources.** What is missing is a v2 artifact for it to operate on.

### How much of this task PR #99 delivered

**Direct acceptance-criteria coverage: 0 of 12.** None of the PRD's checkboxes
can be ticked from PR #99. (`prd.md` carries 12 `- [ ]` criteria; an earlier
pass of this file said 11.)

**Indirect contribution: material on exactly one criterion.** The PRD requires
"a one-time v1-to-v2 migration that maps existing fixed routes to explicit
standalone profiles." Before PR #99 the v1 fixed route lived *only* in an
unmanaged GitHub repository variable, so a migration would have had to read
live GitHub state to know what to convert. After PR #99 the route mode is
recorded in the manifest at schema 4 (`codecs.mjs:136-139`), which makes it a
local, versioned, migratable input. PR #99 also demonstrates the exact
version-gated tier pattern (`PROVENANCE_MIN_SCHEMA_VERSION` /
`DURABLE_MIN_SCHEMA_VERSION` / `ROUTE_MODE_MIN_SCHEMA_VERSION`,
`codecs.mjs:164-171`) that a v1 -> v2 cutover would extend, and the
counter-pattern is documented as a "Wrong" example in the spec
(`.trellis/spec/backend/consumer-installer.md:380-390`).

**A caution about double-counting.** The lifecycle machinery this task's PRD
leans on most heavily — pending/active promotion, dry-run, drift, idempotence,
ownership-preserving uninstall — is *not* PR #99's. It predates it, arriving
via `07-24-add-consumer-installer`, `07-25-decompose-consumer-installer-lifecycle`,
and `08-08-installer-durable-lane` (all archived). Crediting PR #99 with it
would overstate what changed on 2026-08-17.

Overall: **roughly 5% of this task, and none of it in the compiled-manifest
lifecycle the task is named after.** Reusable pre-existing v1 infrastructure
covers perhaps another 30% of the *mechanics*, but zero of the *semantics*.

## Gaps vs PRD

Ordered by how much they block the task.

1. **No consumer-owned v2 source artifact exists anywhere.** `.github/sd-review.yml`
   as described in `design.md` appears in no code path.
   **Naming collision, and it is a live hazard**: `DURABLE_WORKFLOW_PATH =
   ".github/workflows/sd-review.yml"` (`scripts/consumer-installer/codecs.mjs:16`)
   is an installer-owned *workflow*, and its source template is
   `examples/sd-review.yml` (`:17`). The design's proposed consumer source
   differs from the managed workflow by exactly one path segment
   (`workflows/`). Two files named `sd-review.yml`, one consumer-owned and one
   installer-owned-and-overwritten, is a foot-gun in every drift, uninstall,
   and support conversation.

2. **Nobody owns parsing the source.** The compiler consumes a decoded
   JavaScript object (`src/routed-review-compiler.js:442`); `decodeSourceContract`
   likewise (`src/protocol-v2.js:595`). YAML parsing exists only as
   `import { parseDocument } from "yaml"` in
   `scripts/validate-action-metadata.mjs:6`, and `yaml` is a **devDependency**
   (`package.json`) in a repository that describes itself as "a dependency-free
   GitHub Action". A consumer-edited YAML source needs a parser that does not
   exist on the shipped path. Either the source is JSON, or a vendored parser
   is in scope, or the dependency-free claim narrows. Undecided.

3. **The compiled manifest has no home.** `design.md` says compiler results are
   written "through the managed `.github/sd-github-review.json` lifecycle" —
   but that path is the *installer ownership manifest*
   (`scripts/consumer-installer/codecs.mjs:8`), carrying schemaVersion, managed
   file hashes, provenance, and the managed variable block. Overloading it with
   compiled review policy conflates two schemas with different owners, different
   change cadences, and different blast radii. A separate compiled artifact with
   its own pending/active pair is the likelier answer, but it is not decided.

4. **No semantic diff.** `--dry-run` today plans file writes and remote actions
   (`scripts/consumer-installer/plan.mjs`). The PRD wants a diff over chains,
   slots, policies, catalog pin, and override exposure. No such comparison
   exists; the nearest primitive is `stableCompiledJson`
   (`src/routed-review-compiler.js:198`) plus digests, which gives
   change-detection but not a human-readable semantic diff.

5. **Managed mode has no control plane.** `compileRoutedReviewConfiguration`
   takes a `catalog` argument (`src/routed-review-compiler.js:442`) but nothing
   resolves one. The PRD's stated dependency
   `07-25-define-consumer-review-control-plane` **does not exist** — not in
   `.trellis/tasks/`, not in `.trellis/tasks/archive/2026-07` or `/2026-08`.
   Managed mode is unbuildable until that gap is named or the task is
   re-scoped to standalone-first.

6. **No Check publication or branch-protection diagnostics.** The names are
   defined (`src/protocol-v2.js:153-154`) and a projection decoder exists
   (`:1324`), but nothing creates a `sd-review / assurance` or `sd-review / gate`
   Check. The only Check this repository actually publishes is
   `sd-github-review/receipt` (`contract/routed-review-setup-v1.json:15`,
   `src/receipt.js:543`). Legacy-Check retirement therefore has nothing to
   retire *to* yet.

7. **The three named child tasks do not exist.** `prd.md` and `design.md` both
   decompose delivery into `07-25-scaffold-routed-review-source`,
   `07-25-migrate-routed-review-configuration-v2`, and
   `07-25-manage-compiled-review-configuration-promotion`. `task.json` records
   `"children": []` and `"subtasks": []`, and none of the three appear in the
   active or archived task trees. `implement.md` opens by ordering work that
   has no owner.

8. **Reserved-label requirement is vacuously true and untested.**
   `review-candidate:*` and `review-slot:*` occur **zero** times outside
   `.trellis/`. The installer's `ROUTING_LABELS` are `review:cheap`,
   `review:deep`, `review:copilot`, `review:none`, `review:auto`
   (`scripts/consumer-installer/codecs.mjs:72-98`) — a disjoint namespace. The
   PRD's "never provision, migrate, reconcile, or remove" holds today by
   absence, but no test pins it, so a future label addition could violate it
   silently.

9. **`overrides.labels` rejection is DELIVERED, at the compiler layer only.**
   `"overrides"` is in the compiler's forbidden composition-lever list
   (`src/routed-review-compiler.js:61`) and the rationale names
   `overrides.labels` explicitly (`:42-43`). Nothing rejects it at the
   installer or source-file layer, so the error would surface at compile time
   rather than at parse/preflight time as `design.md` step 1 implies.

## Open Questions

1. **Where does the consumer source live, and in what format?** Resolving the
   `sd-review.yml` collision and the YAML-parser question together. A
   `.github/sd-review.config.json` (or `.yml` with a vendored parser) removes
   both problems at once.
2. **One manifest or two?** Does compiled review policy join
   `.github/sd-github-review.json`, or get its own pending/active pair?
3. **Is managed mode in scope at all for this wave?** With
   `07-25-define-consumer-review-control-plane` nonexistent, a
   standalone-first cut delivers most acceptance criteria and defers the rest
   coherently.
4. **Should the three child tasks be created, or should the parent absorb
   them?** The current decomposition is documented but unmaterialized.
5. **Does the distribution premise still hold?** The park's resume condition
   requires v1 to actually be distributed to fleet consumers. Last probed
   2026-08-15 (zero consumers). Not re-probed today.
6. **What retires the legacy Check?** `sd-github-review/receipt` is live and
   published (`src/receipt.js:543`); the PRD's retirement sequence assumes the
   two new Checks reach the head first.

## Recommendations

1. **Resolve the two artifact questions before any code.** The source path/format
   (open question 1) and the one-manifest-or-two question (2) are load-bearing
   for every child task. Both are cheap to decide and expensive to unwind.

2. **Scope this wave to standalone mode.** Standalone needs no catalog, no
   control plane, and no credential boundary — `decodeSourceContract`'s
   standalone branch (`src/protocol-v2.js:604-638`) and the compiler's
   standalone path (`src/routed-review-compiler.js:310-330`) are complete and
   tested. Naming the criteria rather than numbering them — the checkboxes are
   unnumbered, and an earlier pass of this file indexed them against a
   miscounted total — a standalone-first cut clears *fresh install*,
   *standalone performs no catalog/control-plane call*, *local-attested
   scaffolding requires an explicit operator choice*, *one-time v1 migration*,
   *install/update/check/reapply/drift/uninstall preserve unrelated content*,
   *first-party profile round trips*, *candidate/slot label lifecycle plus
   `overrides.labels` rejection*, and *setup documentation*. It clears
   *dry-run semantic diff* and *prior-active preservation on failure* only
   partially, since the chain/slot/catalog-pin halves of both are managed-only.
   It does not touch *fresh managed source carries explicit per-lane merge
   policy* or *setup diagnostics for the new Checks*. All of that without
   depending on a task that does not exist. Managed mode moves behind
   `07-25-define-consumer-review-control-plane`, which should be created as a
   real blocker rather than an implicit one.

3. **Make the reachability fix an explicit deliverable, not a side effect.**
   The first PR that imports `routed-review-compiler.js` from a shipped path
   must also remove it from `scripts/check-coverage.mjs:38-47` and add it to
   `npm run check`. `scripts/check-coverage.mjs:35-37` already states this rule;
   honouring it is what converts 451 quarantined lines into gated ones.

4. **Rename the consumer source to eliminate the collision.** Anything but
   `sd-review.yml`. The installer overwrites `.github/workflows/sd-review.yml`
   on every `update`; a consumer who edits the wrong one loses their work with
   no warning that distinguishes the two.

5. **Add a reserved-label guard test now.** Cheap, and it converts gap 8 from
   "true by accident" to "true by construction" before the label set grows.

6. **Create the three child tasks or fold them in, and record which.** Leaving
   `task.json.children` empty while two planning documents name three children
   means the work-loop inventory cannot see the decomposition.
