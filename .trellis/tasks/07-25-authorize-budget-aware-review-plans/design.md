# Budget-Aware Review Authorization Design

## Boundary

This child begins with one active explicit-managed compiled contract. A candidate-selection
command ends with a durable authorized or terminally rejected/deferred plan; an
options query ends with a bounded safe response and no plan identity. It does
not execute a reviewer or reconcile usage.

Preparation freezes exact head and request identity, applies explicit override
rules, binds the candidate's exact prompt-profile identity, and creates the
ordered named-chain proposal. The trusted management step obtains a bounded
control-plane decision. The engine validates the full fingerprint and persists
authorization before exposing dispatch permission.

The command parser accepts only the documented exact grammar and applies the
same trusted-author policy as existing `/review` commands. Candidate commands
override broad route labels for that attempt. Options queries reuse compiled
eligibility and safe availability projection, but stop before attempt identity,
reservation, persistence, or reviewer dispatch. Invalid aliases produce bounded
valid choices; fuzzy matching is forbidden.

A terminal deferral is valid only when the response proves pre-dispatch budget
exhaustion. It records deferred assurance and the lane's explicit merge-policy
mapping for the later gate projection. Every unverifiable, policy,
authentication, framework, or other non-budget failure is a blocking rejection.

## Failure And Rollback

Pre-authorization failure has no reviewer side effect and is idempotently
retryable. Once authorization or possible dispatch exists, uncertainty enters
reconciliation and never advances to another candidate.
