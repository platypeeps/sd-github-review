### The gate now counts outstanding findings only

`_remote_gate` at `~/.agents/bin/sd-ai-command-pack-review-local.py:1945-1970`:

```python
def _remote_gate(
    outcome: str,
    outstanding: int,
    local_policy: str,
    family_gate: Mapping[str, Any],
    *,
    findings_present: bool = True,
) -> dict[str, Any]:
    if outstanding or (outcome == "findings" and not findings_present):
        return {"state": "blocked", "reason": "actionable-local-findings"}
    ...
    return {"state": "eligible", "reason": "local-stage-terminal"}
```

Compare the PRD's quoted pre-#402 form (`if outstanding or outcome == "findings"`). The
`outcome == "findings"` arm is now qualified by `not findings_present`, so a provider that
reports findings and lists them no longer blocks on the outcome string alone — only on the
count of findings still `outstanding`. A `rebutted` finding does not gate.

### Severity and category are already on every finding — the gate just ignores them

This is the single most important finding for the design, and it materially shrinks the
remaining work.

Every normalized finding carries both fields:

- `~/.agents/bin/sd-ai-command-pack-review-local.py:1640-1642` — the single-attempt
  normalizer records `severity` and `family`.
- `~/.agents/bin/sd-ai-command-pack-review-local.py:1803-1822` — the cross-provider merge
  records `severity`, `family`, `families`, `sourceFamilies`.
- `~/.agents/bin/sd-ai-command-pack-review-local.py:1824-1827` — when two providers report
  the same finding, the merged row takes the **maximum** severity, never the minimum.
- `~/.agents/bin/sd-ai-command-pack-review-local.py:69` —
  `FINDING_SEVERITY_RANK = {"unspecified": 0, "low": 1, "medium": 2, "high": 3}` already
  exists and is already used for that max.
- `~/.agents/bin/sd-ai-command-pack-review-local.py:1580-1599` — a second ingestion path
  normalizes integer severities `1/2/3` to `low/medium/high`.

`_remote_gate` receives `outcome`, `outstanding`, `local_policy`, `family_gate` — and reads
none of the per-finding severity or family data. The information is present in the receipt
and discarded at the decision point.

`.prism/rules.json` (repo-owned) confirms the input side is real: it declares eight `focus`
categories and a `severityOverrides` map pinning `bug`/`correctness`/`security` to `high`
and `style` to `low`. So severity arriving at the gate is policy-shaped, not arbitrary.

## Vendored-vs-upstream considerations

**What this repository can change:** effectively nothing on the gate path.

- The pack is a *thin* install (`.sd-ai-command-pack/provenance.json:4`). The only tracked
  executable is the layout resolver. Editing it cannot affect gate arithmetic.
- The gate binaries are at `~/.agents/bin/`, outside the working tree, so a local edit is
  not even a repository change — it would be a machine mutation, invisible to review, and
  destroyed by the next `sd-ai-command-pack` install.
- Upstream PR #406 (merged 2026-08-11) states the boundary in the pack's own words: this
  consumer *"carries no local fork and cannot: its `pack.install-audit` allowlist covers only
  `.sd-ai-command-pack/*.json`."* Since `9a4787a` there is not even a `scripts/` path to
  patch.

**The one genuinely local lever:** `.prism/rules.json` is repo-owned (`git ls-files` tracks
it; the pack only owns `rules.schema.json`, per `provenance.json`). Narrowing `focus` — for
example dropping `docs` and `style` — would reduce advisory volume immediately and requires
no upstream anything. The PRD rejects this at `:131-133` on the grounds that it suppresses
signal rather than fixing a gate that blocks regardless of rule configuration. That reasoning
still holds: it changes how many advisory findings arrive, not whether an advisory finding
can terminate. It is worth keeping as a **stopgap**, not as the fix.

**What must land upstream:** the severity/category-aware gate, the `remoteGate` distinction,
the second disposition value, the tests for AC3 and AC6, and the SKILL.md text for whatever
new control appears. All of it is `sd-ai-command-pack`.

**Evidence trail is already filed.** Upstream PR #406 is **merged** (closed 2026-08-11 by
`sdelmas`). Its body carries this repository's PR #70 evidence verbatim into
`08-07-local-finding-rebuttal-channel`, including the severity/category requirement and the
"escape is structurally unreachable in this topology" argument. So the upstream PRD already
has the requirement; what it lacks is the PR #99 miscitation evidence added to this PRD at
`:135-187` on 2026-08-16, which post-dates PR #406.
