# Repo Audit — sd-github-review @ 2eeca60 — 2026-07-25

Mode: full · Depth: standard · Dimensions: architecture, design, correctness, security, testing, documentation, bloat, performance, dependencies, tooling, release-hygiene, improvements, consumer-impact

## Verdict

The repository has a strong green baseline—130 tests, syntax checks, metadata validation, and the root production dependency audit all pass—but it is not release-ready without remediation. The audit found 7 verified P1 issues, 12 plausible P2 issues, 3 plausible P3 issues, and no P0 issues. The most urgent risks are incorrect or duplicate reviewer dispatch, third-party receipt authority, installer path escape, untested shipped process boundaries, and a release that does not contain the current installer or working PR-Agent template.

## Findings

### Correctness

#### [A-001] P1 · S · Verified — Authorized Copilot rerequests are suppressed as duplicates
- evidence:
  - `src/receipt.js:476` — a new authorized attempt can return `dispatchAllowed: true`.
  - `src/operations.js:401` — any prior exact-head Copilot review is treated as already satisfied.
  - `src/operations.js:412` — the new attempt is recorded as already present without a new request.
- why: A valid same-head rerequest creates a new receipt but does not request a new Copilot review.
- fix: Ignore prior completed reviews when the authorization names a distinct rerequest attempt, while retaining pending-request deduplication.

#### [A-002] P1 · S · Verified — A PR-number override can route one PR and mutate another
- evidence:
  - `src/index.js:138` — `pr-number` is parsed independently with permissive `Number.parseInt`.
  - `src/index.js:179` — routing metadata still comes from `event.pull_request` when present.
  - `src/index.js:212` — file enumeration uses the independently parsed PR number.
  - `src/index.js:235` — reviewer lookup and mutation use the independently parsed PR number.
- why: A mismatched override combines one PR's labels, author, size, and head with side effects on another PR; malformed suffixes such as `12garbage` are also accepted.
- fix: Strictly parse the complete decimal value and bind it to the event PR, or fetch all routing metadata for the explicit target.

#### [A-003] P1 · M · Verified — Concurrent begins can duplicate durable receipts and wedge an identity
- evidence:
  - `src/receipt.js:486` — receipt absence is checked before a separate Check Run create.
  - `src/receipt.js:519` — each creator can authorize dispatch after rereading only its own visible Check Run.
  - `src/receipt.js:323` — later visibility of duplicate logical identities makes subsequent reads fail.
- why: Concurrent runs can both create and dispatch for one logical identity, after which query and finalize fail closed without a reconciliation path.
- fix: Deterministically elect one authoritative Check Run before dispatch and represent duplicate creates as non-authoritative reconciliation evidence.

#### [A-011] P2 · S · Plausible — Lower-priority label conflicts can block fixed modes and trusted commands
- evidence:
  - `src/index.js:179` — labels are normalized before trusted-command precedence is resolved.
  - `src/router.js:71` — conflicting route labels throw immediately.
  - `DESIGN.md:174` — configured mode and trusted commands are documented above labels in precedence.
- why: A fixed workflow mode or maintainer command cannot recover a PR that carries conflicting labels.
- fix: Resolve configured mode and trusted commands before parsing label selection.

#### [A-012] P2 · S · Plausible — External calls have no execution timeout
- evidence:
  - `src/github.js:156` — GitHub `fetch` calls have no abort signal or per-attempt timeout.
  - `scripts/consumer-installer.mjs:89` — synchronous `gh` calls have no timeout.
- why: A stalled network response, credential helper, or `gh` process can hang the Action or installer until the platform kills the job.
- fix: Add bounded per-attempt aborts and child-process timeouts with explicit terminal timeout errors.

#### [A-013] P2 · M · Plausible — An interrupted update can leave pending state that cannot resume
- evidence:
  - `scripts/consumer-installer.mjs:633` — the pending manifest is written before the workflow replacement.
  - `scripts/consumer-installer.mjs:478` — any workflow/hash mismatch is rejected, including the known old workflow after interruption.
- why: A crash between those writes leaves the installer unable to distinguish its prior managed workflow from an operator edit.
- fix: Preserve the prior workflow hash in pending state or stage both artifacts so recovery can resume safely.

### Security

#### [A-004] P1 · M · Verified — Third-party PR-Agent receives durable-receipt authority
- evidence:
  - `examples/pr-agent-on-demand-review-router.yml:28` — the whole job receives `checks: write`.
  - `examples/pr-agent-on-demand-review-router.yml:90` — the same job token is passed into the PR-Agent container.
  - `src/receipt.js:86` — receipt state is trusted from canonical JSON in Check Runs without a separate signature.
- why: A compromised reviewer image can forge or mutate the receipt namespace used for exact-head deduplication and finalization.
- fix: Separate route, reviewer, and finalization jobs; give PR-Agent only finding-publication permissions and pass a bounded acknowledgment to a dedicated receipt writer.

#### [A-005] P1 · M · Verified — Installer writes can escape through symlinked path ancestors
- evidence:
  - `scripts/consumer-installer.mjs:404` — only the Git worktree root is resolved.
  - `scripts/consumer-installer.mjs:438` — fixed destinations are joined without canonicalizing ancestors.
  - `scripts/consumer-installer.mjs:242` — directory creation and rename follow existing symlinked ancestors.
- why: A repository-controlled symlink such as `.github/workflows` can redirect fixed-name installer writes outside the selected checkout.
- fix: Reject symlinked or non-directory ancestors beneath the canonical root and recheck immediately before rename or removal.

### Testing

#### [A-006] P1 · M · Verified — Shipped process boundaries are untested and CI has no coverage gate
- evidence:
  - `README.md:38` — consumers invoke `scripts/install-consumer.mjs` as the production CLI.
  - `test/consumer-installer.test.js:7` — tests import the engine and replace the real GitHub CLI boundary with a fake.
  - `action.yml:193` — `src/index.js` is the shipped Action entrypoint, but tests call `runAction` directly.
  - `.github/workflows/ci.yml:20` — CI runs tests and syntax/metadata checks without coverage enforcement.
- why: CLI stdin, process exits, real `gh` arguments, redaction, Action event loading, and top-level failure behavior can regress while CI remains green.
- fix: Add subprocess tests with a PATH-injected fake `gh`, Action event/output smoke tests, and conservative coverage floors for critical files.

### Release hygiene

#### [A-007] P1 · M · Verified — The only release lacks the current installer and working PR-Agent template
- evidence:
  - `README.md:38` — current setup guidance depends on `scripts/install-consumer.mjs`.
  - `SETUP-PR-AGENT.md:19` — current docs say the released `uses: docker://` pattern is incompatible.
  - `v0.1.0:examples/pr-agent-router.yml:61` — the only tag still uses the incompatible Docker Action form.
  - `scripts/consumer-installer.mjs:530` — managed manifests record a template hash but no source tag or commit.
  - `docs/RELEASE_CHECKLIST.md:83` — the release gate lacks package/tag synchronization and public-surface compatibility rules.
- why: Release-pinned consumers cannot follow current setup guidance, and an untagged installer run cannot later prove its reviewed source or upgrade path.
- fix: Publish a reviewed release with the installer and corrected templates, record source identity, synchronize first-party pins, and enforce version/changelog/migration rules.

### Architecture

#### [A-008] P2 · M · Plausible — Routing responsibility is split across protocol, event, and mode composition
- evidence:
  - `DESIGN.md:51` — routing policy is assigned to `src/router.js`.
  - `src/protocol.js:975` — protocol code implements route floors and local-evidence policy.
  - `src/index.js:170` — standalone mode constructs risk context and dispatches reviewers.
  - `src/operations.js:333` — durable mode repeats policy and dispatch composition.
- why: Policy, codecs, and side effects cannot evolve independently, and standalone/durable behavior can silently diverge.
- fix: Extract a normalized routing-policy service plus shared risk-context and dispatch services; keep protocol codec-only and entrypoints as composition roots.

#### [A-009] P2 · M · Plausible — The consumer installer is an undecomposed lifecycle subsystem
- evidence:
  - `scripts/consumer-installer.mjs:115` — the module owns GitHub CLI transport.
  - `scripts/consumer-installer.mjs:273` — it owns configuration and manifest validation.
  - `scripts/consumer-installer.mjs:487` — it owns lifecycle planning and mutation execution.
  - `scripts/consumer-installer.mjs:836` — it also owns CLI argument parsing.
- why: Transport, schemas, planning, persistence, and orchestration cannot change independently as migration and rollback behavior grows.
- fix: Split codecs, pure planning, transport, persistence, and orchestration into focused modules behind the existing CLI composition root.

### Design

#### [A-010] P2 · M · Plausible — The Action contract is neither operation-specific nor mechanically aligned
- evidence:
  - `action.yml:6` — one global surface requires a token while making operation payloads optional.
  - `src/operations.js:517` — `acknowledge` completes without constructing a GitHub client.
  - `DESIGN.md:257` — durable `run-external-reviewer` semantics are documented by route rather than by newly authorized adapter request.
  - `scripts/validate-action-metadata.mjs:206` — validation checks mappings, not runtime names, defaults, applicability, or semantics.
- why: Callers grant unused inputs and invalid combinations fail only at runtime; metadata, runtime parsing, and documentation can drift independently.
- fix: Define one versioned tagged operation contract or thin operation wrappers, then validate metadata and documentation from the shared contract.

#### [A-020] P3 · S · Plausible — Exported review-label registry is mutable
- evidence:
  - `src/router.js:167` — a mutable `Set` is exported and consumed by routing entrypoints.
- why: Any importer can alter label behavior for the process despite the binding being declared `const`.
- fix: Keep the set private and export an `isReviewLabel` predicate or immutable value collection.

### Performance

#### [A-014] P2 · S · Plausible — Empty sensitive-path policy still paginates every PR file
- evidence:
  - `src/index.js:207` — standalone file loading does not check `patterns.length`.
  - `src/operations.js:340` — durable auto routing fetches files before parsing sensitive patterns.
  - `src/github.js:215` — file enumeration can make 30 sequential API requests.
- why: Consumers that disable sensitive-path routing still pay avoidable latency and rate-limit cost on every automatic review.
- fix: Parse patterns first and enumerate files only when at least one pattern requires evaluation.

#### [A-015] P2 · S · Plausible — Same-head rerequests load the same receipt set twice
- evidence:
  - `src/receipt.js:396` — rerequest validation queries and decodes current-head records.
  - `src/receipt.js:486` — `begin` immediately loads the same identity records again.
- why: Each authorized rerequest duplicates Check Run latency and quota use, amplified by pagination.
- fix: Load one current-head snapshot and pass it through rerequest validation and identity lookup.

#### [A-022] P3 · M · Plausible — Consumer installation serializes independent GitHub CLI calls
- evidence:
  - `scripts/consumer-installer.mjs:90` — every call uses blocking `spawnSync`.
  - `scripts/consumer-installer.mjs:117` — independent inspection calls run serially.
  - `scripts/consumer-installer.mjs:563` — independent remote mutations are also serialized.
- why: Cold installation latency is the sum of each process startup and network round trip.
- fix: Use asynchronous child processes and bounded concurrency for independent reads and mutations while preserving ordered state transitions.

### Dependencies

#### [A-016] P2 · S · Plausible — OpenCode plugin dependency is unlocked and apparently unused
- evidence:
  - `.opencode/package.json:2` — `@opencode-ai/plugin` uses a range with no nested lockfile.
  - `.opencode/package.json:4` — the declaration is the only repository reference to the package.
- why: OpenCode can install different executable dependency trees over time, outside the root lockfile and root dependency audit, for a package with no visible import.
- fix: Confirm implicit runtime need; remove it if unnecessary, otherwise lock and audit the nested install.

### Tooling

#### [A-017] P2 · S · Plausible — The prescribed local full-check skips every CI package gate
- evidence:
  - `scripts/sd-ai-command-pack-full-check.sh:1033` — generic default stages do not include this package's script names.
  - `package.json:12` — the repository defines `check`, `validate:metadata`, and `test`.
  - `.github/workflows/ci.yml:20` — CI runs all three package-specific gates.
  - `.github/PULL_REQUEST_TEMPLATE.md:14` — contributors are directed to the generic local full-check.
- why: The prescribed local gate can pass after skipping everything that CI enforces.
- fix: Add a durable repository-specific full-check configuration or wrapper that runs the same three commands as CI.

### Improvements

#### [A-018] P2 · L · Plausible — Guarded lifecycle support does not cover every first-party profile
- evidence:
  - `README.md:24` — the lifecycle installer is limited to event-driven PR-Agent.
  - `README.md:88` — Copilot-only and durable consumers still perform setup manually.
  - `SETUP-COPILOT.md:55` — Copilot setup requires manual workflow copying and configuration.
- why: Supported profiles do not all receive manifest ownership, dry-run, drift checks, guarded updates, rollback, or uninstall.
- fix: Make installation profiles declarative and add lifecycle coverage for Copilot, standalone PR-Agent, durable PR-Agent, and local-attested modes.

### Consumer impact

#### [A-019] P2 · M · Plausible — Installer cannot adopt existing manual installations
- evidence:
  - `SETUP-PR-AGENT.md:207` — consumers are instructed to copy workflows manually.
  - `scripts/consumer-installer.mjs:458` — an existing workflow without a manifest is rejected when it differs from today's template.
  - `SETUP-PR-AGENT.md:43` — setup documentation offers no guarded adoption path.
- why: Existing manual or v0.1.0 consumers cannot transition to managed updates without deletion or bespoke reconciliation.
- fix: Add explicit adoption for approved historical hashes with semantic dry-run, confirmation, and a documented manual fallback.

### Bloat

#### [A-021] P3 · S · Plausible — `hasManagedFiles` is an unreachable public export
- evidence:
  - `scripts/consumer-installer.mjs:890` — the only repository reference is the function's own export.
- why: The helper expands the supported surface without serving an entrypoint or test.
- fix: Delete the export; its private `pathExists` dependency remains live elsewhere.
